# TemplateEditor Guide

## Purpose

`TemplateEditor` is the admin UI for placing and editing input overlays on top of a static printable template image. The template base is `PrintableTemplate.backgroundImage`. The overlays sit above the image in a separate overlay plane.

File:

```txt
components/TemplateEditor.tsx
```

Routes:

```txt
/dev/test-template-editor
/dev/test-template-editor/[pageId]
```

## High-Level Layout

The editor has two main areas:

- Left panel: template metadata, input list, settings form, save/render controls.
- Right stage: scaled letter-page preview containing the static template plus overlays.

The preview page uses:

```tsx
style={{ aspectRatio: `${template.layoutSettings.widthIn} / ${template.layoutSettings.heightIn}` }}
```

For current letter templates, that is `8.5 / 11`.

## Template Loading

The dynamic editor route loads a template by `pageId`:

```txt
app/dev/test-template-editor/[pageId]/page.tsx
```

It calls `getPrintableTemplate(pageId)` and passes the result to:

```tsx
<TemplateEditor initialTemplate={template} />
```

The fallback route `/dev/test-template-editor` loads all templates and redirects to the first one.

## Editor State

The component stores:

- `template`: the editable `PrintableTemplate`.
- `selectedInputId`: the current selected input.
- `status`: save/render status text.
- `dragStateRef`: active drag/resize state for overlays.

On initial load, `normalizeTemplateInputs()` fills missing placeholders, normalizes checkbox/radio option bounds, and ensures "Other" options have text boxes.

## Input List

The left panel lists `template.inputDefinitions`. Selecting an input updates `selectedInputId`.

Each input shows:

- `label`
- `typeId`

## Adding Inputs

The `Add input` button creates a new `TemplateInputDefinition`:

- `inputId`: generated from `Date.now()`
- `typeId`: defaults to `textLine`
- `label`: `Input N`
- `placeholderText`: generated by input type
- `bounds`: default percentage rectangle
- `displaySettings`: white background, 11pt, left aligned

The new input is appended and selected.

## Removing Inputs

The `Remove` button deletes the currently selected input. After removal, the editor selects the first remaining input, if any.

## Bounds Editing

Every input has these editable numeric fields:

- `xPercent`
- `yPercent`
- `widthPercent`
- `heightPercent`

They are clamped by `normalizeBounds()`:

- Width and height are clamped from `1` to `100`.
- X and Y are clamped so the rectangle stays inside the page.

Bounds are percentages of the preview page. This makes positions stable across different display sizes.

## Dragging and Resizing

Input overlays can be moved and resized directly on the page.

Move:

- Pointer down on the overlay body.
- Movement delta is converted from pixels to percent using the current page size.
- `xPercent` and `yPercent` update live.

Resize:

- Pointer down on the resize handle.
- Movement delta updates `widthPercent` and `heightPercent`.

The same drag infrastructure also supports checkbox/radio option boxes and "Other" text boxes.

## Display Settings

Each input supports:

- `useWhiteBackground`: whether rendered text gets a white background block.
- `fontSizePt`: output font size.
- `textAlign`: currently supported in the type model, and used for preview style.
- `dateFormat`: used when `typeId` is `date`.

Date formats:

- `MMDDYY`
- `YYMMDD`
- `MM/DD/YY`
- `YYYY-MM-DD`

`formatInputValue()` applies the date formatting during render.

## Input Types

The editor exposes:

- `textLine`
- `textArea`
- `date`
- `phoneNumber`
- `firstName`
- `lastName`
- `email`
- `number`
- `checkbox`
- `radio`
- `signature`
- `initials`

Changing an input type updates its placeholder. If the type becomes `checkbox` or `radio`, the editor creates a default check option when none exist.

## Placeholders

Placeholders are used in two places:

- Editor overlay labels.
- Test render values when clicking the editor’s PDF/PNG buttons.

Defaults come from:

```txt
lib/printable-templates/placeholders.ts
```

When a label changes, the placeholder updates only if the current placeholder still matches the previous default. This avoids overwriting custom placeholder text.

## Checkbox and Radio Inputs

Checkbox/radio inputs can either be simple checks or option-based checks.

Simple check:

- No `checkOptions`.
- If the render value is truthy, a check mark is drawn inside the input bounds.

Option-based check:

- Uses `checkOptions`.
- Each option has its own `bounds`, `label`, `value`, and `optionId`.
- Render values are matched against `value`, `label`, or `optionId`.

Option controls:

- Add option
- Add other
- Edit option label
- Edit match value
- Toggle "Other option"
- Edit check option bounds
- Edit "Other" text box bounds
- Remove option

## Other Options

An "Other" option can have:

- A checkbox/radio check position: `bounds`
- A separate text box position: `textBoxBounds`
- Placeholder text: `textPlaceholderText`

The editor lets admins drag and resize both the check mark location and the text box location.

During render, choice values can include:

```ts
{
  selected: string | string[];
  otherText?: string;
}
```

The selected option gets checked, and `otherText` is drawn into the option’s text box.

## Save Behavior

The `Save` button sends the full current template to:

```txt
PUT /api/templates
```

Current behavior:

- The API upserts the template by `pageId`.
- It writes the updated template list into `data/printable-templates.json`.
- It updates `updatedAt`.

This is currently local-store behavior. Strapi write support is not implemented in the current route.

## PDF and PNG Buttons

The editor’s `PDF` and `PNG` buttons call:

```txt
POST /api/templates/render/pdf
POST /api/templates/render/png
```

The editor sends generated sample values for every input:

- Checkbox with options: all options selected.
- Radio with options: first option or "Other" option selected.
- Checkbox without options: `true`.
- Other inputs: placeholder text.

The response is opened in a new browser tab.

## Preview Rendering

The preview page renders:

```tsx
<img className="template-background-image" src={template.backgroundImage.src} />
<div className="overlay-plane">...</div>
```

Important implications:

- The static base is rendered from the permanent background image asset.
- The same image is used by the PDF and PNG renderers.
- Overlays are separate buttons above the static base.

## Overlay Classes

The overlay plane includes:

- `.template-overlay`: normal input overlay.
- `.check-option-overlay`: checkbox/radio option position.
- `.check-option-textbox-overlay`: "Other" text area position.
- `.overlay-resize-handle`: resize affordance.

The selected input receives a selected style.

## Current Editor Limitations

- There is no undo/redo.
- There is no keyboard nudge support.
- There is no zoom control.
- There is no locked/static overlay mode.
- There is no multi-select.
- There is no snapping/grid.
- Saving writes local JSON only.
- There is no built-in workflow yet for replacing a background image while preserving existing overlays.

## Practical Editing Workflow

1. Open the dashboard at `/`.
2. Click the desired base template.
3. Add or select an input.
4. Drag/resize the overlay into place.
5. Refine bounds numerically.
6. Set label, placeholder, type, font size, date format, and white background.
7. For checkbox/radio fields, define check locations and match values.
8. Save.
9. Use PDF/PNG buttons to inspect rendered output.
10. Repeat until overlay positions line up with the static base.
